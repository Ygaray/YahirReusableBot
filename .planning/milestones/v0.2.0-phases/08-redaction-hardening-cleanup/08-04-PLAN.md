## Plan-time decisions

**Gate scope: `include = ["yahir_reusable_bot"]`, library source only.** This resolves
08-RESEARCH.md's assumption A2 and Open Question 2, which flagged it for plan-time confirmation.
HYG-04's own wording is about "the public surface's type contracts", and the library package is that
surface. Test files use dynamic-eval patterns (`get_type_hints` with `localns=` overrides), hand-
written doubles, and monkey-patching that a checker reasonably objects to, and `scripts/` holds a
standalone stdlib scaffolder written years before any checker existed — pulling either in would
inflate the first-run baseline for zero public-surface benefit, which is precisely the flooding the
backlog entry warned against. Widening to `tests/` and `scripts/` is a clean follow-up once the
source baseline is burned down; it is recorded as such, not silently dropped.

**Gate form: a standalone script, not a pytest test.** Running pyright inside `uv run pytest -q`
would make the suite depend on a provisioned Node runtime and would push feedback latency past the
sub-5-second budget `08-VALIDATION.md` is built on. The project already has a standing gate that is
not a pytest test — `uv run ruff check` — and this one sits beside it. What IS a pytest test is the
diff logic itself, which is pure, synthetic, and fast.

**Where the RED-first obligation lands.** GATE-02 requires every requirement to ship a test that
genuinely fails against pre-fix source. For HYG-04 the testable artifact is the diff gate's logic,
not pyright itself (a third-party tool needs no regression test here). `tests/test_pyright_baseline.py`
is therefore committed first and is genuinely RED — the module it imports does not exist, so
collection fails outright, exactly as `tests/test_redact_sink.py` was RED before `sink.py` existed.
