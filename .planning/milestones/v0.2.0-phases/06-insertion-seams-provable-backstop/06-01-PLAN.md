<assumption_delta_decision>
The assumption-delta checkpoint fired on two signals in this phase's scope: `pluralization`
("a second `structlog.configure()` call") and `optional` ("the OPTIONAL structlog processor").

**The noun that is now primary:** *the redaction seam*, generalized over two variants — a
**sink seam** (`RedactingWriter`, required, load-bearing, renderer- and chain-order-independent) and
a **processor seam** (`redaction_processor`, optional, additive, chain-order-sensitive). Until this
phase the project's working model was singular: "the structlog processor chain is *the* redaction
integration point." That model produced the derived rule recorded in `STATE.md` — *"`redact/` stays
stdlib only, plus `structlog` inside `processor.py` alone."*

**Decision: `promote`.** `RedactingWriter` is promoted to the primary representation of the seam and
the processor is demoted to a detail of one optional variant. Two concrete consequences, both taken
in this phase rather than deferred:

1. The structlog-coupled module set under `redact/` is promoted from the hardcoded singular
   (`processor.py` alone) to an **enumerated allowlist** — `processor.py` and `verify.py` — while the
   *load-bearing* module (`sink.py`) is deliberately kept stdlib-only. That asymmetry is the point:
   the primary seam must work against ANY file-like target, so its module must not couple to the
   logging framework at all. This is why plan 06-02 puts `assert_redaction_active` in a new
   `verify.py` rather than co-locating it in `sink.py` as RESEARCH.md's Pattern 3 sketch suggested.
2. `verify.py` locates redaction processors by a **marker attribute** (`REDACTION_PROCESSOR_MARKER`),
   never by importing `redaction_processor` by identity. The identity coupling would re-encode the
   singular assumption (one blessed processor) and would make the self-check unbuildable before the
   processor exists.

**Companion invariant test (accepted, built in plan 06-04):**
`test_redact_sink_never_imports_structlog` — a grimp assertion, in the same idiom as the existing
`test_config_module_never_imports_pydantic`, that the load-bearing sink declares no `structlog` edge,
paired with a self-proof driving the same scan against a synthetic edge so it cannot go vacuous. It
goes RED the instant a future phase reintroduces the singular "redaction is a structlog concept"
assumption into the primary module.

**Accepted debt (an `add-alongside` sub-decision, recorded deliberately):** the *wiring* variants are
not yet unified under one proof. `assert_redaction_active` introspects `structlog.get_config()` and
therefore proves only D-54 recipe 1. D-54 recipe 2 (`sys.stderr = RedactingWriter(sys.stderr, ...)`)
has no introspection path this phase — it is proven by test (D-55) but not provable at a consumer's
runtime. What would force a later promote: a consumer adopting recipe 2 as its *sole* wiring, or a
second non-structlog render target appearing. Until then the asymmetry is documented in SEAM-08
(plan 06-04) rather than papered over.
</assumption_delta_decision>

## Flagged assumptions carried by this plan

- **A1 (RESEARCH assumptions log), inherited here:** the sink's `__getattr__` delegation makes
  `RedactingWriter` a usable stand-in for `sys.stderr`, but a Python-level proxy cannot intercept
  `sys.stderr.buffer.write(...)` or a raw file-descriptor write. Recipe 2 therefore covers text-mode
  writes only. Documented as a known limitation in SEAM-08 (plan 06-04), not silently carried.
- **RESEARCH Pitfall 3 (boundary-class under-redaction):** a `name=value`-shaped pattern whose value
  boundary class excludes a quote or backslash can under-redact a secret whose own value contains one
  of those characters inside already-JSON-escaped text. This is a property of the *consumer's chosen
  pattern shape*, not of this seam, and literal mode (`RedactionPattern.literal`, shipped Phase 5)
  sidesteps it entirely. The JSON round-trip test below deliberately uses a delimiter-free sentinel so
  the structural claim (redaction does not break JSON syntax) is not conflated with that separate
  concern. Recorded in SEAM-08's pattern-authoring guidance (plan 06-04).
