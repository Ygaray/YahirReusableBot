<objective>
Close two independent `lifecycle/identity.py` footguns, both RED-first:

- **LIFE-02 (H14, D-42):** `write_pid_atomic` (`identity.py:62-87`) can double-close the temp fd — the
  happy path calls `os.close(fd)` at `:76`, then the except-path re-closes at `:82-85` guarded only by
  `except OSError: pass`. If the integer was reused for an unrelated descriptor between the two closes,
  the guarded close silently closes the WRONG fd and the `except OSError: pass` hides it. Fix: set
  `fd = -1` immediately after the first `os.close`, and make the except-path close `if fd != -1`.
- **LIFE-03 (H15, D-39):** the non-Linux `/proc`-absent degrade returns the raw `proc_marker` as the
  sentinel (`_read_proc_cmdline` `:218`); `_argv_matches_marker` basenames `argv[0]` (`:191`) but
  compares to the UN-basenamed `proc_marker` (`:192`), so a path-shaped marker (`b'/usr/bin/thebot'`)
  breaks the documented "degrade to True" — and also fails real Linux matching for a path-shaped
  marker. Fix: basename BOTH sides — `prog == Path(proc_marker.decode('utf-8','replace')).name`.

Purpose: two one-to-four-line fixes on OS-process-lifecycle primitives, grouped by file (same-module
findings, not a ROADMAP-mandated pairing — the Phase 1/2 precedent of grouping same-file findings into
one plan). LIFE-02 introduces the repo's FIRST use of pytest's `monkeypatch` fixture — a deliberate
house-style extension (pytest core, NOT a mocking library), flagged the same way Phase 1 flagged
`conftest.py` and `pytest.raises()`.
Output: a guarded-close `write_pid_atomic`, a basename-both-sides `_argv_matches_marker`, and extended
`tests/test_identity.py` regressions; GATE-01 green.
