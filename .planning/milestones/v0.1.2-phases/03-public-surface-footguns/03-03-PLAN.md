<objective>
Fix the `registry/` casefold symmetry — the ROADMAP-mandated **MATCH-01 + MATCH-02 pairing** (both
land in this one plan; fixing one without the other leaves the matcher half-consistent):

- **MATCH-02 (H13, D-34):** validate every `spec.name` inside `CommandRegistry.__init__`'s existing
  single derivation pass (`registry.py:39-48`): **non-empty AND already-casefolded**
  (`name == name.casefold()`), raising `ValueError` otherwise. This is deny-by-default / fail-LOUD-at-
  construction (mirrors `is_transient`'s posture and `panelkit.py:207`'s curated-command assert). An
  empty name can no longer claim blank input; an uppercase name can no longer be permanently
  unmatchable. `build_registry` forwards to `CommandRegistry`, so the `ValueError` propagates through
  it for free.
- **MATCH-01 (H06, D-35):** `match_command` (`match.py:59-61`) currently slices
  `rest = stripped[len(spec.name):]` — the UN-folded original with the FOLDED keyword length — so a
  length-changing casefold (`ß`→`ss`, `ﬁ`→`fi`) mis-slices. Fix: map the keyword boundary back to an
  index in the ORIGINAL stripped string via a new `_keyword_boundary(stripped, name)` helper
  (RESEARCH.md §"Code Examples #1", the verified O(n) incremental scan), and slice the arg from there —
  preserving the RAW-case `ParsedCommand.arg` contract.

**Two independent axes, one contract (carry this framing):** the length mis-slice bites from the INPUT
side (`ßtatus`) even with perfectly-normalized names, so the two fixes are genuinely independent and
MUST land together. Because D-34 guarantees `spec.name` is already casefolded, the keyword test stays
`folded.startswith(spec.name)` (no per-match casefold of the name).

**MATCH-01 algorithm (bake in, cite):** use RESEARCH.md §"Code Examples #1". The scan accumulates each
ORIGINAL character's `len(ch.casefold())`; the boundary is the first original index where the running
total reaches `len(spec.name)` EXACTLY. If it jumps PAST the target without hitting it exactly, the
boundary falls inside a single char's multi-char fold — provably NOT a real word-boundary match (no
Unicode casefold expansion contains whitespace, verified across all 0x110000 codepoints), so return
`None` → the existing `continue`. It relies on the verified property
`(a+b).casefold() == a.casefold()+b.casefold()`. See RESEARCH.md §"Common Pitfalls #4" for why a naive
`==`-only scan is buggy and the adversarial overshoot case.

Purpose: the most algorithmically novel fixes in the phase, done once the simpler patterns are proven.
Output: registration-time name validation; a boundary-correct raw-arg slice; two NEW test files
(`test_registry.py`, `test_match.py`) kept separate per the 1:1 `test_<module>.py` convention; GATE-01
green.

**Process note:** Wave 3 of 5, serial. Depends on Plan 02 (03-02) green. Direct-to-`main`,

where it previously silent-failed at match). Name this in the phase SUMMARY for the close-out.
