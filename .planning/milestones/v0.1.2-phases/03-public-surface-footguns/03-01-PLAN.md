<objective>
Make `SchedulerEngine.remove` idempotent for an already-gone job id (SCHED-01, H16, D-38): catch
the host scheduler's lookup-miss error and swallow it with a debug log, so a reconcile
double-remove race or a misfire-coalesce race is a no-op success rather than a raised exception —
directly analogous to `Path.unlink(missing_ok=True)`, and symmetric with `register`'s tolerant
posture.

**Verified RESEARCH correction (bake in, cite so the executor doesn't "fix" it back):** CONTEXT.md
D-38 says "catch `JobLookupError`". `apscheduler` is NOT a dependency of this hub (absent from
`pyproject.toml`/`uv.lock`, not importable) and MUST NOT be added — that would contradict
`SchedulerEngine`'s documented host-scheduler-agnostic design. The correct, dependency-free fix is
`except KeyError:` — apscheduler's `JobLookupError` IS a `KeyError` subclass (verified against
apscheduler 3.x source). See RESEARCH.md §"Common Pitfalls #2" and §"Code Examples #2".

Purpose: close the smallest, most isolated footgun first while the codebase is fully green, proving
the `except KeyError:` dependency-free pattern before the more novel fixes land.
Output: idempotent `remove()` with a stated docstring contract; a new `tests/test_engine.py` RED-first
regression proving the swallow; GATE-01 green.
