<objective>
Implement LIFE-04 (H18): give `ReadyGate.run` a first-class fatal outcome a consumer branches on
directly, retiring the stop-Event-overload hack — WITHOUT changing the ok / clean-shutdown paths'
semantics or emit ordering. Three locked decisions land together (they are one coupled change the
tests exercise as a unit):

- D-44: define a 3-member `ReadyOutcome` enum (ONLINE / SHUTDOWN / FATAL) in `ready_gate.py`, with a
  `__bool__` override so ONLY ONLINE is truthy; `run` returns `ReadyOutcome` not `bool`; export
  `ReadyOutcome` from `lifecycle/__init__.py` `__all__`.
- D-45: append an additive `fatal: bool = False` field to the frozen `HealthResult` dataclass
  (after `severity`); `Severity` unchanged.
- D-46: on a failing probe, `on_fail` fires first (unchanged), then if `result.fatal` -> log at
  `critical` and return `ReadyOutcome.FATAL` immediately (no `stop.wait()` re-probe); `on_online`
  does NOT fire. The non-fatal failing path stays byte-identical to today.

Purpose: closes the last lifecycle finding of milestone v0.1.2 and unblocks WeatherBot's de-hack.
Output: a rewritten gate + additive DTO field + export, all proven by a RED-first test file, plus
the de-hack documentation deliverable naming the two consumer sites for the repin.
</objective>
