<objective>
Close CFG-01 (H03): the ReloadEngine PHASE-2 reconcile-failure path rolls back, restores, logs,
and re-raises, but never fires the injected `on_rejected` hook — so the host's "reload rejected"
Discord alert is silently skipped on a reconcile failure (PHASE-1 fires it correctly). The fix
fires `on_rejected` before the re-raise, matching the PHASE-1 precedent, per D-31/D-32.

Purpose: A rejected reload must be operator-visible on BOTH rejection paths, not just PHASE-1
validation. A silently-skipped alert leaves the operator blind to a rejected reload running on the
old config (observability/availability).
Output: `tests/test_reload.py` (first-ever coverage for `config/reload.py`) with a RED-first
regression test, then the one-line-binding + one-call fix in `reload.py`.

Sequencing: This is Wave 1. Plans 02 and 03 depend on it and run after it — each plan runs the
full `uv run pytest -q` suite (GATE-01) as its wave gate, and every plan commits a deliberately-RED
test, so plans are sequenced (never same-wave) to guarantee a RED test never overlaps a sibling's
full-suite gate (the Phase-1 "Plan 03 waits on 02" lesson).
</objective>
