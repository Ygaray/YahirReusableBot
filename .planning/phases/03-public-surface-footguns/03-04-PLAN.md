<objective>
Fix the `retry.py` `burst_size` coupling — the ROADMAP-mandated **RELY-02 + RELY-03 pairing** (both in
this one plan):

- **RELY-02 (H09, D-36):** `_within_burst_wait` (`retry.py:157-167`) computes
  `step = burst_spread_s / (burst_size - 1)`, which raises `ZeroDivisionError` when `burst_size == 1`
  (the `attempt_number == burst_size` early-return at `:161` only shields the first attempt). Fix:
  **guard, degrade — do not raise.** Add a `burst_size <= 1` guard BEFORE the division, returning
  `burst_spread_s` (the spread base, no jitter). With `burst_size == 1` each burst is a single attempt
  and `stop_after_attempt(2)` bounds the schedule before the degenerate value is ever consumed, so the
  guard only has to NOT crash.
- **RELY-03 (H10, D-37):** `two_burst_wait` fires its mid-pause at `attempt_number == burst_size`,
  **blind to the stop bound** — it only receives `retry_state.attempt_number` and structurally CANNOT
  see the stop bound, so a standalone caller pairing it with their own `stop_after_attempt(N)` can
  desync. Fix: **document the precondition loudly in the docstring; add no coupling machinery.** State
  that a standalone caller MUST pair it with `stop=stop_after_attempt(2 * burst_size)`. `build_retrying`
  already couples correctly (`retry.py:258-260`), the wired path every real consumer uses. Pin the
  mid-pause-at-`attempt_number == burst_size` behavior with an executable test so a future silent
  decouple fails.

**RELY-03 linchpin (do not let a reviewer push for machinery):** the function cannot self-check because
it never receives the stop bound — a hard assert is physically impossible and a matched-pair factory is
over-built for an unreachable footgun (a Deferred Idea, no consumer calls `two_burst_wait` standalone).
The docstring precondition + the executable mid-pause pin is the honest ceiling.

**tenacity call-order fact (bake into the RELY-02 test design, cite):** tenacity calls `wait` BEFORE
`stop` (verified, RESEARCH.md §"Common Pitfalls #3"): `_run_wait` → `_run_stop` →
`_post_stop_check_actions`. The wait callable's return is discarded if stop fires, but the wait callable
STILL EXECUTES and can still raise on the terminal attempt. So a RELY-02 test that only checks the
RETURNED value at `attempt_number == burst_size` (the branch that already worked pre-fix) stays GREEN
before AND after — the RED assertion must exercise `attempt_number != burst_size` with `burst_size <= 1`
(directly, or via `build_retrying(attempts_per_burst=1, ...)` driven to its second attempt, exactly as
RESEARCH empirically reproduced).

Purpose: the `retry.py` pairing, requiring care with tenacity's wait-before-stop order.
Output: a guarded-degrade `_within_burst_wait`; a loud precondition docstring on `two_burst_wait`;
extended `tests/test_retry.py` regressions; GATE-01 green.

**Process note:** Wave 4 of 5, serial. Depends on Plan 03 (03-03) green. Direct-to-`main`,
RED-parent/GREEN-child commits per finding (D-13).
</objective>
