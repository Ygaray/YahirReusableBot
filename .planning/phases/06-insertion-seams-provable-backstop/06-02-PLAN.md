**Deliberate decoupling from plan 06-03:** `redaction_processor` does not exist yet at this wave. The
ordering sub-check must therefore NOT import it. It discovers redaction processors by reading
`REDACTION_PROCESSOR_MARKER` off each entry in the live chain, so this module builds, tests and ships

attribute on the closure it returns. This is not a workaround for wave ordering — it is the correct
contract, because a consumer's own hand-written redaction processor must be able to participate too.

## Flagged assumptions carried by this plan

- **UNRESOLVED probe row — REDACT-07 (`unclassified`).** The deterministic edge probe classified
  REDACT-07 as `unclassified` and it is carried forward as an explicit flagged assumption rather than
  auto-resolved into a `must_haves` predicate. Reviewed manually here: REDACT-07 has no data-shape edge
  of its own because it takes no input — it reads global configuration state. Its real edge axis is
  *inconclusiveness*, which is covered by the must-have truths above (three distinct failure classes,
  never a false pass) and by the prohibition. **No silent drop: the row is surfaced here, not
  discarded.** If verification wants a mechanical edge criterion for REDACT-07, the "never a false
  pass" criteria are it.
- **RESEARCH open question 2, resolved as recommended (assumption A1).** `assert_redaction_active`
  ships with a hard raise and NO unwrap convention for a consumer proxy nested around the writer. This
  satisfies "never a false pass" completely, at the cost of a false negative for a consumer using a
  lazy-stream-resolving proxy — a shape WeatherBot's own `_LiveStderr` uses. The mitigation is
  message-level, not mechanism-level: the raise tells the consumer exactly how to reorder their
  wrapping. Revisit only if the human-gated WeatherBot repin actually hits this friction (rule of
  three); do not build the unwrap protocol speculatively.
- **Private-attribute coupling has no upper version pin (RESEARCH Pitfall 5).** `pyproject.toml` pins
  the logging library with a lower bound only, so a future release could rename the private file
  attribute this introspection reads. That is why the missing-attribute branch is its own message
  naming the installed version — the coupling is accepted, but it is made to fail loudly and
  legibly rather than silently.

`assert_redaction_active(*, deep: bool = False) -> None` — keyword-only option so the call site reads
unambiguously at a consumer's composition root. Order of operations:
1. Read the live configuration once. Take the logger factory. If it is not an instance of either
   `structlog.PrintLoggerFactory` or `structlog.WriteLoggerFactory`, raise `ValueError` naming the
   actual type and stating that this introspection only knows how to read those two.
2. If that factory does not expose the private file attribute the shipped factories store their
   `file=` argument in, raise `ValueError` in its OWN wording — it must name the installed library
   version (read it from the library's version attribute) and say that the introspection is coupled to
   an implementation detail that has changed. This branch exists because the dependency is pinned with
   a lower bound only; collapsing it into the next branch would report a dependency upgrade as a
   consumer wiring bug (RESEARCH Pitfall 5).
3. If that file target is not an instance of `RedactingWriter`, raise `ValueError` naming the type it
   actually found AND stating the fix for the nested-proxy case: wrap the stream with the hub's writer
   FIRST, then wrap that in any additional proxy the project needs. This is the deliberate hard raise
   of RESEARCH open question 2 — no unwrap convention is built this phase.
4. When `deep` is set, call `probe_redaction_path()` on the located instance and let its `ValueError`
   propagate. That method owns the empty-pattern-set and disabled cases and is already proven never to
   touch the wrapped target, so this module adds no sentinel handling of its own.
5. Call `_warn_if_processor_misordered()` last, so an ordering warning never pre-empts a hard wiring
   failure.
Return `None` on success. Emit no log line, perform no write, and mutate no configuration — the whole
point is that this is safe to call at boot AND mid-run in production.

`_warn_if_processor_misordered() -> None` — read the live processor chain. Collect the indices of
entries whose `REDACTION_PROCESSOR_MARKER` attribute is truthy (use a defaulted attribute lookup so an
entry that does not carry it is simply skipped, never an error). If there are none, return silently —
a consumer who did not adopt the optional processor has nothing to be warned about. Otherwise find the
index of the first entry that is an instance of `structlog.processors.ExceptionRenderer`; that one
public class covers both shipped exception formatters and any future built-in following the same shape,
which is why a hardcoded name list is wrong here. If no such entry exists, emit a generic "could not
