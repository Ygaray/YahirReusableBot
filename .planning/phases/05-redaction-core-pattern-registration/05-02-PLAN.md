**Termination correction — this is load-bearing, do not simplify back.** `_blows_budget` must run
each `search` as its own step and compare CUMULATIVE elapsed against `_REDOS_BUDGET_S` after EVERY
individual search, returning True the moment the budget is exceeded. It must NOT build one large
probe string and time a single search: `re` cannot be interrupted, so a single search over a long
probe with a catastrophic pattern runs to completion and hangs the vetting call — the exact failure
this check exists to prevent. Because the fine tier increments by +2 repeats, an exponentially-growing
pattern's per-rung cost rises by at most about 4x, which bounds the overshoot past the budget instead
of leaving it unbounded. Iterate shapes outermost or ladder outermost as you prefer, but the
cumulative check between every search is mandatory.
