## Doc Drift (new — surfaced by this audit)

**DOC-DRIFT-01 — a de-hack site was documented at a path that does not exist.**
Eleven planning artifacts name `weatherbot/ops/daemon.py` as the LIFE-04 gate-return de-hack site.
That file does not exist; the real path is `weatherbot/scheduler/daemon.py`. The drift originates in
the planning source of record (`.planning/backlog/HUB-HARDENING-REPORT-v0.1.2.md:213`) and was
inherited verbatim by `04-CONTEXT.md`, `04-RESEARCH.md`, `04-01-PLAN.md` (including an `<automated>`
grep check that asserts the wrong path), `04-01-SUMMARY.md`, `04-02-SUMMARY.md`, `04-VALIDATION.md`,
`04-VERIFICATION.md`, `REQUIREMENTS.md:115`, and `STATE.md:101`.

Impact was contained — the repin executor found the real path and the de-hack landed correctly — but
the phase-4 deliverable ("the two WeatherBot sites are named in the phase summary") technically names
a nonexistent file, and the plan's automated check passed by grepping for the wrong string.
`ECOSYSTEM.md` is **clean**; it correctly references `weatherbot/scheduler/wiring.py`.

**DOC-DRIFT-02 — the de-hack deliverable undercounted the sites.**
The phase named 2 consumer sites. The actual repin required 3: `weatherbot/ops/selfcheck.py`
`to_health_result` also had to classify `CONFIG_INVALID` as fatal for the new `HealthResult.fatal`
field to ever be set. Without it the `ReadyOutcome.FATAL` branch would have been unreachable in the
consumer. A hub-side deliverable that enumerates consumer de-hack sites should enumerate the site
that *produces* the input, not just the sites that *consume* the outcome.

## Assessment

The milestone did what it set out to do. All 18 defect requirements plus the standing GATE-01 gate
are satisfied, verified against live source rather than SUMMARY narrative, with RED-first two-commit
ancestry independently re-derived per fix. The riskiest structural property — three source files
touched by multiple phases — holds without regression. The one contract change that crosses the repo
boundary (LIFE-04) was proven end to end in production, not just in tests.

What the audit adds is a documentation-quality finding, not a correctness one: the phase-4 cross-repo
deliverable named a nonexistent consumer path and undercounted the de-hack sites, and the drift
survived a plan-level automated check because that check grepped for the same wrong string it was
meant to validate. Worth noting as a pattern — an automated check derived from the same source as the
claim it verifies cannot catch an error in that source.
